# ADR 142: Type-First Browser Navigation

## Status
**Accepted** - 2024-12-03

## Context

The preset browser previously used a **vendor-first** navigation pattern:

```
Vendor → Type → Category → Library → Preset
Omni → Keys → Acoustic → Trilian Creative → Grand Piano
```

This required users to:
1. Know which vendor contained the sound they wanted
2. Navigate into that vendor to see available types
3. Remember which vendors had which sound types

For a unified preset library spanning Ableton, Native Instruments, and Omnisphere, this created a fragmented browsing experience. Users thinking "I want a bass sound" had to check multiple vendors separately.

### Previous Structure (On Disk)

The physical folder structure remains vendor-first due to symlink organization from Omnisphere restructuring (ADR 020):

```
Instruments/
├── Ableton/
│   ├── drums/
│   └── fx/
├── NI/
│   ├── inst/
│   ├── keys/
│   └── synth/
└── Omni/
    ├── arp-bpm/
    ├── bass/
    ├── drums/
    ├── fx/
    ├── inst/
    ├── keys/
    └── synth/
```

## Decision

Implement **type-first** navigation:

```
Type → Vendor → Category → Preset
Keys → Omni → Acoustic → Grand Piano
Keys → NI → Piano → Noire Grand
```

This inverts the hierarchy so users:
1. Start with the sound type they want (Keys, Bass, Synth, etc.)
2. See all vendors that offer that type
3. Drill down into vendor-specific categories

### Key Design Decisions

1. **Aggregate types across vendors** - The `types-index.json` lists all unique types with their contributing vendors
2. **Split JSON per type-vendor combination** - Files like `keys-omni.json`, `keys-ni.json` enable lazy loading
3. **Fixed vendor colors** - Each vendor has a consistent color regardless of context:
   - Ableton: Yellow `hsl(50, 90%, 50%)`
   - NI: Cyan `hsl(180, 80%, 45%)`
   - Omni: Magenta `hsl(300, 70%, 55%)`
4. **Color propagation through depth** - When navigating into a vendor's subfolders, text stays colored to match the parent vendor

### TypeFirstAdapter

New adapter in `interface/src/lib/services/adapters/typeFirstAdapter.ts`:

```typescript
export class TypeFirstAdapter implements BrowserAdapter {
  private typeIndex: TypeIndex | null = null;
  private loadedFiles: Map<string, PresetNode> = new Map();

  async getTypes(): Promise<TypeInfo[]> {
    await this.loadTypeIndex();
    return Object.values(this.typeIndex!.types);
  }

  async getVendorsForType(typeId: string): Promise<VendorInfo[]> {
    await this.loadTypeIndex();
    return this.typeIndex!.types[typeId]?.vendors || [];
  }

  async loadVendorFile(typeId: string, vendorId: string): Promise<PresetNode> {
    const filename = `${typeId}-${vendorId}.json`;
    if (!this.loadedFiles.has(filename)) {
      const response = await fetch(`/data/${filename}`);
      const data = await response.json();
      this.loadedFiles.set(filename, data);
    }
    return this.loadedFiles.get(filename)!;
  }
}
```

### Browser Store Updates

`browserNavigationStore.svelte.ts` tracks:
- `selectedType` - Current type (keys, bass, synth, etc.)
- `selectedVendorColor` - Color of the selected vendor for propagation

```typescript
let selectedVendorColor = $state<string | null>(null);

// When user clicks a vendor folder at depth 0
set selectedVendorColor(value: string | null) {
    selectedVendorColor = value;
}
```

### Component Color Propagation

Colors flow through the component hierarchy via CSS custom properties:

**FolderNavigationColumn.svelte** - Emits color on click:
```svelte
onclick={() => onFolderClick?.(folder, 0, group.color)}
```

**UnifiedGestureBrowser.v6.svelte** - Stores and passes color:
```typescript
function handleFolderClick(folderName: string, depth: number, vendorColor?: string) {
    if (depth === 0 && vendorColor) {
        browserNavigationStore.selectedVendorColor = vendorColor;
    }
}
```

**VendorBrowserMode.svelte** - Applies color to subfolder buttons:
```svelte
<div class="column narrow" style="--vendor-color: {vendorColor};">
    <button class="selection-button vendor-colored">
```

**PresetGrid.svelte** - Applies color to preset names:
```svelte
<div class="patches-results" style="--vendor-color: {vendorColor};">
```
```css
.patch-card h4 {
    color: var(--vendor-color, var(--browser-text-primary));
}
```

### Fixed Vendor Color Mapping

Previously, colors were assigned by alphabetical index within each type, causing inconsistency when a type had only one vendor. Now colors are fixed per vendor:

```typescript
const VENDOR_COLOR_MAP: Record<string, string> = {
    'Ableton': 'hsl(50, 90%, 50%)',   // Yellow
    'NI': 'hsl(180, 80%, 45%)',       // Cyan
    'Omni': 'hsl(300, 70%, 55%)',     // Magenta
};

function getVendorColor(vendorName: string, fallbackIndex: number): string {
    return VENDOR_COLOR_MAP[vendorName] || FALLBACK_COLORS[fallbackIndex % FALLBACK_COLORS.length];
}
```

## Navigation Flow

### Before (Vendor-First)
```
[Omni] [NI] [Ableton]          ← Pick vendor first
   ↓
[Keys] [Bass] [Synth]          ← See types in that vendor
   ↓
[Acoustic] [Electric]          ← Categories
   ↓
[Piano] [Rhodes]               ← Presets
```

### After (Type-First)
```
[Keys] [Bass] [Synth] [Drums]  ← Pick type first
   ↓
[Omni] [NI]                    ← See vendors with that type (color-coded)
   ↓
[Acoustic] [Electric]          ← Categories (colored by vendor)
   ↓
[Piano] [Rhodes]               ← Presets (colored by vendor)
```

## Consequences

### Positive
- **Faster discovery** - Users find sounds by type without knowing vendor organization
- **Unified view** - All Keys sounds accessible from one starting point
- **Consistent colors** - Each vendor always has the same color
- **Visual hierarchy** - Color propagation shows vendor context at all depths
- **Lazy loading preserved** - Per-type-vendor JSON files load on demand

### Negative
- **Physical structure unchanged** - Disk still organized vendor-first (symlink-based)
- **Two source structures** - JSON is type-first, disk is vendor-first (requires mental mapping for debugging)

### Neutral
- **Regeneration required** - Run `npm run generate-instruments` after folder changes
- **Backward compatible** - Old vendor-first adapters still exist but unused
